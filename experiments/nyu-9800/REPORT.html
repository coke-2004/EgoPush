从一个箱子理解整个系统

第一次去搬哪个箱子，取决于机器人刚刚看到了什么。要把它放在哪里，取决于 NYU 模板以及现场哪些地方能走。机器人把这两件事接起来，靠的是一份持续核对的箱群位置记录。

看箱群→认出邻居→选箱与落点→边看边搬→放手复查

以种子 9814 为例。机器人在附近出生时只知道要摆 20 箱和字形尺寸。它沿箱群外围巡查，确认数量后现场算出搬运次序。日志中的第一条 pick 0 14 表示“第 1 趟搬内部编号 14 的箱子”。靠近后，它用手边的箱面把双手对正，抓起，再借其它静止箱子找落点。第一次松手后，视觉估计箱心偏了 1.5 cm、箱边偏了 0.84°。两项都合格，程序才把完成数改成 1，并开始寻找下一箱 12。

跑完整场，再由独立评分器读出 20 箱的真实终态。9814 的箱心 RMSE 为 1.58 cm，最大角差 1.38°。前一段的 1.5 cm 描述第一箱在手边的视觉复查；这里的 1.58 cm 描述整场真实终态与模板的吻合程度。

程序架构与数据流

从仓库根目录执行 python -m arrangement 输出目录 种子，Python 首先运行 __main__.py。它读模板、创建本体、把二者交给控制器，并挂上轨迹记录函数。随后控制器的 run() 接管这一场。下表按调用方向阅读。

谁调用谁交给下一层什么返回或产生什么
入口 → RBY1随机种子、箱子数、模型和抓取动作生成散箱和机器人初态，建立 MuJoCo 世界
入口 → Controller.run本体对象、以米计的字形槽位控制器循环巡查、取箱、运箱、复查
Controller → 本体与感知要看的相机、是否寻找抬起的箱子当前底盘系箱心、侧面角度或可见性
Controller → plan / route已观测的箱群、设计槽位；当前目标和障碍整轮取放配对；本段可行的局部拐点
Controller → RBY1 → MuJoCo平移速度、转动指令、头部角度、手臂关节动作轮子和手与地面、箱子接触；下一帧观测随之改变
入口 → score；回放 → render终态物理坐标和记录的 qpos；回放另读配置result.json、轨迹与同步视频
哪些信息进入控制？ 识别使用机载 RGB-D、相机标定与关节角。速度控制还读取瞬时角速度。场景生成、记录、事后评分和观众跟拍可接触仿真真值。虽然实现共享同一个本体对象，控制逻辑没有用箱体真值、物体标签、外部摄像头或底盘世界位姿来选箱和导航。这是代码的数据流约定。

九台相机怎样合看同一群箱子

机器人有前向 +x、左向 +y 的底盘坐标系。每台相机拍到箱子的像素后，用像素位置、焦距和深度反算三维点，再用相机相对底盘的安装位置与朝向把点换到底盘系。头动时，程序沿关节链用当前关节角重新计算外参。这样，左前镜头和头部镜头看到的同一物体，就能在同一把尺上比较。

镜头组提取的信息何时配合
机身前、左、后、右 · 4 台找橙色区域，在相近高度找水平箱顶，拟合朝向与中心巡查全扫使用四台；前向巡查也可补看抓取区
底盘左前、右前、后 · 3 台低视角常看见立面；从可见近边和已知半边长 13 cm 推回中心搬运期全扫纳入静止邻箱；遮挡时可提供另一条视线
头部、底盘近摄 · 2 台近距离检查手边箱心、是否抬起；从侧面深度点估角手边找中心按头部、近摄、前巡依次尝试；估角按头部、前巡、近摄尝试

观测裁去距离超过 4.15 m 的点。同一次扫描中，控制器顺序汇集各镜头的箱心；新点距已收集点不足约 24 cm 时保留先收集的点。由此得到“现在看见了哪些中心”。跨时间给这些中心找回编号，还要做下一节的匹配。

导航通常发一段 0.30 s 的运动指令，再观测一次。默认优先看先前命中较多的镜头，每 11 次导航循环全扫一次；单镜头匹配不足三个也会提前全扫。巡查全扫用四向镜头，搬运全扫可用九台。停车、转头、抓取和复查各有自己的节奏，所以每台镜头都没有固定拍摄频率。录像里九路同时显示，是按同一物理时刻重绘的可见画面。

箱子消失再出现，编号怎样接上

第一次扫描到一组箱子时，程序选第一个点作原点，把每个箱子的相对二维坐标存入 nodes。例如 nodes[7] 表示内部 7 号在箱群坐标系中的位置。measured[7] 则表示这一轮真正匹配到的 7 号在当前底盘系中的位置。两份数据各有用途。

  1. 预测。拿上次参照箱在车身旁的位置、记忆中的箱间向量和朝向估计，算出各编号这次大概会出现在车身哪一侧。
  2. 让整组箱子投票。机器人刚走过一步，许多预测点会一起偏移。程序枚举 1 m 内的候选偏移，比较哪个能让更多邻箱的残差小于 18 cm；随后做一对一最小代价分配，只接纳残差小于 26 cm 的配对。
  3. 更新参照。用间距至少 0.9 m、长度前后一致的箱对估计箱群相对车身的转角，从当前匹配里选与整体偏移最一致的箱子作参照。参照可以换。巡查中若至少匹配四箱，会用一致的新测量以 13% 权重微调旧坐标。
  4. 确认新箱。巡查全扫中至少有三个旧点匹配成功，且一个检测离所有已知位置都超过 50 cm，才新建编号。至少命中三次、底盘系观测相对首次记录变化超过 22 cm，才计入确认数。巡查结束后保留稳定节点并重新连续编号。
视野全空时会怎样？ 单镜头不够就扩大扫描；仍无匹配时，停车、转头并沿最后参照的方位短程试探。有限次数后仍找不到就停止。编号的依据是几何邻域；遮挡过久或构型对称时，仅凭外观无法保证找回身份。

先决定搬哪箱，再边走边修正

模板只给出笔画内部的几何关系。开场机器人沿已见箱群的外围选择观察点，直到确认所需数量。随后 plan() 在箱群附近尝试字形的不同平移和朝向。在 16 cm 栅格上，它同时检查两个站位：车身能否停到源箱前，持箱后能否进到目标前。还要考虑这次放下的箱子会不会堵住下一笔，以及抓箱附近是否还有可用的参照。规划优先尝试保留两个附近参照的方案，再尝试较少参照的方案。

输出是一串 (源箱内部 ID, 目标槽位坐标)。第一箱也靠仍在地面的散箱确定落点；以后可用的参照还包括已经摆好的箱子。拿起的源箱退出静止节点集。落箱通过复查后，用实测位置登记为新的已放节点，例如第一箱登记在 nodes[20]。程序因此知道哪一趟已经完成，之后仍靠几何匹配认出眼前的实体。

持箱时没有看见“槽位”，怎么知道还要走多少？

槽位在地上没有标记。假设记忆中目标在 A 箱前方 0.60 m、左侧 0.20 m。此刻看见 A 在车前 1.00 m、右侧 0.30 m。为便于心算，假设箱群轴与底盘轴刚好平行，那么目标就在车前 1.60 m、右侧 0.10 m。抓取点在车前约 0.842 m，横向居中，因此手到目标的误差约为向前 0.758 m、向右 0.10 m。这些数字是算法示例。

目标在底盘系的位置 ≈ 当前看见的邻箱位置 ＋ 旋转到车身方向的“邻箱到目标”向量

relative() 对每个已匹配的邻箱都计算一次，再按坐标取中位数。route() 用当前障碍位置和车身、持箱外廓检查直达路径；需要绕行时在约 13 cm 网格上做 A* 搜索并简化拐点。navigate() 对准下一个拐点，每走一小段就重算误差，进展停滞还可重规划。由此产生前进、后退或横移指令。机器人估计的是箱群与车身的相对变换，没有把轮速或地面纹理累计为房间中的行驶轨迹。

轮子如何移动，双手如何抓正放正

场景把边长 26 cm、质量 0.6 kg 的自由方箱随机放在 5.2 × 4.8 m 区域，初始中心间隔大于 0.80 m。机器人从距最近箱子 1.05–2.2 m 处随机朝向出发。控制器不知道这些随机坐标。MuJoCo 每 2 ms 积分一次；RBY1 把平移和转动指令换成四轮执行器速度，利用陀螺仪的瞬时转速抑制偏转。向右平移时，实际位移由轮地接触产生。

  1. 抓前对正。从相邻深度像素恢复箱侧面的法向，用方箱四面每隔 90° 重复的性质投票估角。底盘围绕手前的抓取点小步旋转，并同时修正横向偏差。位置和箱边角度都接近目标后，执行已有的双臂双手关节序列，再从近处视觉确认箱子抬起来。
  2. 持箱找路。恢复相对箱群的行驶方向，持箱导航的平移速度上限为 0.23 m/s。间隔检查箱子是否仍在手上。若视觉提示掉箱，尝试从附近观测中分离掉落物、重新抓取；身份含糊或恢复次数耗尽会中止。
  3. 放前微调。结合静止邻箱给出的槽位位置与手中箱面的朝向，修正底盘。松手前的精对准目标为角差约 1.4° 以内、位置差约 3.2 cm 以内，循环有上限；能否接受这次放置要看松手后的实测。
  4. 放后核查。反向执行关节动作释放箱子，低头重新看箱面。局部角差 ≤3.8° 且箱心偏差 ≤7.5 cm 才通过，否则重新抓放，单箱最多九次释放。整个过程靠手与箱子的接触力完成。

这一批 20 场留下 399 次放手复查，全部在首次释放通过。由此能验证本批次完成摆放时的精度；这批数据没有测到重抓分支面对歪箱时的成功率。逐次复查数据

怎样判成功，失败的那一场发生了什么

9800–9819 每个种子各跑一次。19/20 通过，95% Wilson 区间为 76.4%–99.1%。成功场次的箱心 RMSE 中位数为 1.58 cm，范围 1.28–2.93 cm。上一轮换用另一组种子得到 18/20；两批比例的差异不足以归因于算法改动。

验收项评分器如何计算通过标准
搬运完整性按释放计数分段，在每段有箱心高于 28 cm 的最后一帧取最高箱的实体编号并去重；终态检查中心离地高度登记 20 次、20 个不同箱子，20 箱中心高度距 13 cm 小于 1.5 cm
字形位置两组箱心分别去中心，尝试 72 个初始转角；交替做一对一分配和刚体旋转拟合，取平均平方误差最低的结果RMSE <10 cm，最远单箱 <18 cm；允许平移和旋转，保留字形尺度与手性
箱边朝向把每箱水平朝向与拟合后的字形轴比较，按方箱的 90° 对称性折回，汇总绝对角差角差 RMS ≤5°，最大角差 ≤10°

为什么要同时看均值和最差箱？ 9812 的整场 RMSE 是 2.93 cm，但其中一箱偏离槽位 10.64 cm。它仍满足 18 cm 的单箱上限。这个数也能超过手边复查的 7.5 cm，因为一个是在当时的局部视觉估计中测量，另一个使用全部真实终态与模板的事后对齐。

失败个案 · 9801 前 19 箱完成，第 20 箱抬起后，程序报 lost box neighborhood at lift (19)。终态 19 箱落地。能确定的是搜索结束后仍无法恢复静止箱群的对应；日志不足以判定是哪台相机被挡或哪个编号认错。剩余一箱远离目标，导致整场 RMSE 达到 105.82 cm。

复现一次，或更换字形与本体

在仓库根目录运行下列命令。本机现有环境可用 .conda/bin/python 代替 python。新环境使用 Python 3.11、锁定依赖及可用的 EGL 图形驱动；录像还需 ffmpeg 与 Noto Sans CJK 字体。

python -m pip install -r requirements.lock.txt
python -m arrangement runs/demo 10001
python -m arrangement.render runs/demo/seed_10001 demo.mp4

config.json 记录种子、本体和设计槽位；result.json 给出搬运数、实体数、终态误差和失败原因；trace.npz 保存关节与箱体状态、阶段和完成数，供离线重绘。通常每 200 个物理步留一帧，约 0.4 s。重复同一种子应换一个输出目录。批次汇总由 report.py 编写 CSV、直方图和 Markdown；本 HTML 是针对本次版本编写的阅读指南。

换字形。 复制 nyu.json，为每个槽位写名字和以米为单位的二维中心，再传 --shape my_shape.json。入口接受 3–20 个不同槽位，机器人还需要足够大的进出空间和可见参照。现有成功率仅测过 NYU。

换本体。 用 --robot 模块名:类名 指定适配器，提供运动、转头、抓放、RGB-D、相机外参和轨迹接口。抓取点、九个相机角色、视场角、底盘与持箱外廓及抓取动作都需与新本体一致。建议先验证一个箱子的轮驱接近与视觉抓放，再测整套字形。本体接口说明

迁移到室内的边界。 现版使用已知尺寸、统一橙色的方箱、标定深度、较平整地面与已知数量。外观相同且邻域对称、长时间全遮挡或深度噪声较大时，身份匹配会变难。真实室内环境和其它本体尚未由这 20 次仿真验证。
